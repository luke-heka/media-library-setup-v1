How it works, in plain English

You point Claude at a folder. The tool counts what is there, proposes a flat structure, draws it as two pictures, and moves nothing until a named person approves exactly what was shown. Later, optionally, it sends audio to OpenAI to get timestamped transcripts, at a price it quotes first.

Who touches what

1Your AI

check

Reports Python version, whether Drive for Desktop, ffmpeg and a key are present, with the fix for each. Reads nothing in your library.

2Your AI

scan, plan

Counts files, depth and near-empty folders; recognises Keynote-style packages as one item; proposes Videos / Photos / Audio / Documents / _Index per event. Writes only to its own state folder.

3You

visualise, then approve

Two HTML pages open locally. A fingerprint of the exact plan is stamped into the plan file. You say yes, by name.

4The tool

apply

Refuses without the fingerprint match, the visuals and a name. Moves each file, then logs it. Never overwrites. Clears only folders it emptied. Prints what it could not move.

5You

rollback, any time

Previews the restore, changes nothing without a name, puts every file back under its original name and folder casing. Verified byte-identical in the test suite.

6You, then OpenAI

transcribe

Measures every file with ffprobe, prints the dollar figure and the disk it will use, and stops. With --yes it converts audio locally and POSTs it to OpenAI. Paid results are banked before anything else is written.

7The tool

manifest, search

Free and offline. One table per event of every file, and a line-by-line search of the transcripts that answers with the file and the minute.

Source-supported example requests

  • Organise my Google Drive media folder — check, scan, plan, visualise, then waits for a yes
  • Put my library back the way it was — rollback preview, then rollback with a named approval
  • Transcribe just the Brisbane workshop — transcribe --only "Brisbane…" with the cost quoted first
  • Find the bit where someone talks about pricing — search pricing, returns event / file [mm:ss]

Security review

Six checks against the shipped source. Findings carry one ID per root cause. Nothing was run against real data or live services.

Pass

1. Hidden instructions

SKILL.md, README and references were read for override attempts, authority claims and concealed actions. None. Provenance markers are present as declared HTML/comment text and a zero-width signature in headings; they are labelled as provenance, claim no runtime role, and were checked to contain no instructions. Docs tell the AI to stop on silence and refuse deletion, not the reverse.

Pass, with L1 noted

2. Credential access

The only secret is the OpenAI key. Read from OPENAI_API_KEY or a 0600 file the tool creates in the user's config folder via a hidden prompt or stdin (medialib/keystore.py). Never printed: key --check and check report only the character count. Sent only in the Authorization header to api.openai.com. No keychain, browser, SSH or cloud credential reads. L1 (Low): check prints the Drive mount path, which contains the signed-in Google account email, and that output is read by the hosted AI. Local disclosure to the user's own session; no transmission by the tool. Remediation if wanted: mask the account segment in the printed path.

Pass

3. Network calls

One destination in source: https://api.openai.com/v1/audio/transcriptions (medialib/transcribe.py, ENDPOINT, used by OpenAIWhisper.transcribe). Reached only inside transcribe --yes, after the estimate is printed and a key is present. Payload: the converted mp3 bytes, model name, response format, timestamp flag. Retries on 429/5xx with backoff; 401 and no-credit errors stop with plain-English messages. IPv4 is pinned for the call and restored after. No downloads, no fetch-and-execute, no telemetry. Observed requests during this review: zero (the test suite substitutes a fake transport).

Pass

4. Destructive commands

No user file is ever unlinked. Moves happen only in medialib/apply.py, gated by check_gate: plan present, both visuals present, approver name of two or more characters, and the plan fingerprint matching the one stamped at visualise time. shutil.move targets are checked with an exists/symlink/samefile guard so nothing is overwritten. Folders are removed with rmdir only when the plan emptied them and they are truly empty. Every move is one committed row in a SQLite journal (medialib/journal.py); rollback restores newest-first, restores original folder casing, and marks rows restored so failed ones stay pending for retry. A 0.x rollback.csv is imported on first open. Package folders are moved whole. The tests prove a nested fixture with a package, sidecars and a name collision restores byte-identical. Limitation: state files live in the user's own home folder; a user editing plan.json before visualise could approve a plan of their own making. That is not a boundary between users.

Pass

5. Opaque code

Twelve short, readable Python modules, no minification, no packed data, no eval/exec/compile, no dynamic imports, no shell strings. Subprocess calls use fixed argument lists: open/xdg-open/os.startfile for the two local HTML files, /usr/bin/xattr for Finder colours, ffprobe and ffmpeg for audio. smoke.sh asserts every import across the package is standard library. HTML comes from three template files filled with string.Template. No binaries anywhere in the skill.

Pass, with L2 noted

6. Permission and persistence scope

No hooks, no scheduled tasks, no shell-profile edits, no config edits outside its own folders, no package installs by the tool. Writes: ~/active/media-library-setup/<library>/ state (overridable), ~/.config/media-library-setup/openai-key, and inside the library only the approved moves plus _Index/ transcripts and manifests. L2 (Low): the optional transcription step depends on ffmpeg, which the docs ask the person to install through brew, winget or apt, unpinned. Bounded: optional, user-run, from the OS package manager, never fetched by the tool.

Scoring: two distinct Low findings at 5 points each = 10. Executable scripts present, so ×1.3 = 13, rounded up = 13. Review score = 100 − 13 = 87. No blocking finding, coverage complete, so the band is "No blocking findings in reviewed scope". The number is triage, not certification.

Business fit

Good fit: anyone with event footage, client shoots, workshop recordings or podcast audio scattered across a Drive, who wants to find a clip by what was said rather than by filename, and who wants the reorganisation to be reversible. Cost to organise is nothing; cost to transcribe is quoted per library before anything is sent, at $0.006 per minute (price checked on the OpenAI pricing page 2026-09-08 and printed with every estimate).

Not a fit: libraries that must keep deep bespoke folder trees (the tool flattens to two levels and says so up front); shared drives where several people reorganise at once (one state folder per library path, no locking); anyone who cannot install Google Drive for Desktop and whose files are only in the cloud (the tool works on local folders only).

Dependencies: Python 3.9+; Google Drive for Desktop only if the media lives in Drive; ffmpeg and an OpenAI key only for transcription. Google offers no Drive for Desktop on Linux.

Claims checked against source: "no file is ever deleted" holds (no unlink of library files anywhere); "it can all be undone" holds for moves and is tested, and the docs now say transcripts and manifests written afterwards are new files that stay; "nothing is charged until you confirm" holds (no request without --yes and a key).
